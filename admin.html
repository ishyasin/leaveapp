Import historical leave

Developer only. Manually back-fills a leave record from an old spreadsheet or paper record — set who it's for, who requested it, who approved it (or the rejection reason), and the original dates. This bypasses the normal self-only/approval-flow rules that apply to everyone else, since it's recreating something that already happened rather than raising something new. The same one-request-per-day check still applies, so it won't silently create a duplicate for a date that's already on record.

Times are stored as entered in your browser's local time zone — worth a quick sanity check on the calendar afterwards if precise timing matters for a TOIL record.

Reset app data for go-live

Developer only. Permanently deletes every leave request, bank holiday, restricted day, capacity override, and Clinical Rota Completed / DSR complete flag, resets each site's leave-capacity threshold back to its default, and clears the audit log — so the app starts completely clean for real use. User accounts, roles, and site assignments are not touched — nobody needs to be recreated. This cannot be undone.

Reset the on-call rota only

Developer only. Permanently deletes every on-call shift, swap request, on-call bank holiday and rota period so the rota can be built again from scratch. Leave data, user accounts, who is in each site's on-call pool, swap-approval settings, the Huddle Board and Quick Links are not touched, and the audit trail keeps a record of the reset. This cannot be undone — the daily backup email is your safety net.

Easter egg

Developer only. A hidden game on the portal home page. While it is off, nothing happens however the code is typed. While it is on, anyone signed in who types the secret code on the home page and presses Enter opens it. Only you can switch it on or off or change the code. The code is stored only as a salted hash: it can never be read back, so if it is forgotten, set a new one. Changing the code stops the old one working straight away. Every change is written to the audit log (never the code itself).

Themes people can choose

Developer only. Ticked themes appear in everyone's own theme picker (top bar). Unticked themes are Developer-controlled: only you can assign them, from Users → Edit theme or “Apply a theme” above. The Default theme is always available. People keep whatever theme they already have even if you untick it later.

Theme by month

Give a calendar month its own theme. During that month everyone sees it automatically, taking priority over their personal theme (but not over anyone you have locked into a theme); in months left on “No theme” each person's own theme applies as normal. It repeats every year — e.g. October → Halloween, December → Christmas, April → Easter. The seasonal themes include animations (Halloween: glowing carved pumpkins and ghosts; Christmas: falling snow and reindeer; Easter: bunnies and chicks), which are switched off for anyone whose device is set to reduce motion.
